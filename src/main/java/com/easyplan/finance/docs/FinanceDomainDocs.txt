[ 기능 - 가계부 생성 기능 및 정책 ]

요청 주소
  - POST /api/ledgers/{memberPublicId}

인터페이스 및 메서드
  - LedgerCommand Interface / createLedger()

요청 파라미터
  - 멤버 식별자, 가계부 타입, 가계부 이름, 가계부 설명, 사용자 선택 Template 상수 리스트
  - (publicId, type, name, description, accounts)

검증 정책
  - LedgerPolicy Interface / canCreate()
  - 회원 상태를 검증한다. isActive()
  - 가계부 생성 한도를 검증한다.

프로세스
  - 1. 가계부 이름, 설명, 타입과 사용자가 선택한 기본 계정 항목을 Request로 받는다.
  - 2. 해당 멤버의 권한 상태에 따라 생성 가능한 가계부 개수가 제한되는데 이를 확인한다.
  - 3. 가계부가 생성될 때 5대 계정 카테고리가 생성된다. 생성된 5개의 카테고리는 다 달라야한다.
  - 4. 기본 계정 항목에 템플릿으로 설정된 계정옵션과 이름을 그대로 가져와서 계정 항목을 생성한다.

[ 기능 - 가계부 이름, 설명 변경 및 정책 ]

요청 주소
  - PATCH /api/ledgers/{ledgerPublicId}
  
인터페이스 및 메서드
  - LedgerCommand Interface / updateLedgerInfo()
  
요청 파라미터
  - 가계부 식별자
  - 쿠키: 멤버 액세스 토큰
  
검증 정책
  - LedgerPolicy Interface / validateForUpdateLedger()
    멤버가 서비스를 사용 가능한 상태인지 검증한다. -> MemberSummary.canUseService()
    변경 대상이 되는 가계부의 소유가 요청자의 것인지 검증한다. -> findByLedgerPublicIdAndOwnerId
    
프로세스
  - 1. 멤버 식별자로 요청자 조회
  - 2. 서비스 사용 가능상태인지 확인
  - 3. 해당 멤버의 아이디와 가계부 식별자로 가계부 조회
  - 4. 이름 및 설명 변경 호출
  
실패 케이스
  - 1. 멤버의 Status가 ACTIVE 상태가 아님.
  - 2. 멤버의 아이디와 가계부의 소유자 아이디가 일치하지 않음
  - 3. 가계부 Status가 ACTIVE 상태가 아님.

[ 기능 - 가계부 사용안함(= 읽기전용) 처리 ]

요청 주소
  - PATCH /api/ledgers/archived/{ledgerPublicId}
  
인터페이스 및 메서드
  - LedgerCommand Interface / archived()
  
요청 파라미터
  - 가계부 식별자
  - 쿠키: 멤버 액세스 토큰
  
검증 정책
  - LedgerPolicy Interface / validateForUpdateLedger()
    멤버가 서비스를 사용 가능한 상태인지 검증한다. -> MemberSummary.canUseService()
    변경 대상이 되는 가계부의 소유가 요청자의 것인지 검증한다. -> findByLedgerPublicIdAndOwnerId

프로세스 및 실패케이스
  - Ledger Model에 대한 CRUD는 모든 기능이 validateForUpdateLedger() 를 통해 검증한다.
    따라서 프로세스 및 실패케이스는 Ledger Model 기본적으로 위 가계부 이름, 설명 변경의
    프로세스와 실패 케이스가 적용된다.
